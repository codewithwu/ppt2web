# ppt2web

把 `.pptx` 转成**可以在浏览器里放映的自包含网页包**。

- **图片无损** —— 嵌入位图字节级原样落盘，不做任何重编码；矢量媒体（SVG）保持矢量
- **内容不丢** —— 文本、表格、图形、图片、主题色全部还原；验收有逐字符断言
- **动画保留** —— 直接解释 PPT 的动画行为树（不是"预设近似"），时机/对象/方向/时长/顺序都对
- **文字矢量化** —— 默认把文字转成字形轮廓：不依赖任何字体、不依赖观看者环境、版式自己算

## 快速开始

```bash
python -m ppt2web convert 某文件.pptx -o out/
# 打开 out/index.html 即可放映
```

**产物零依赖**（双击 `file://` 就能放，不联网）。**转换期**需要 `fontTools`（矢量文字模式用）：

```bash
uv pip install fonttools brotli
```

字体文件要放进项目（见下面「字体」），否则文字会退回 HTML 模式渲染。

## 命令

| 命令 | 作用 |
|---|---|
| `ppt2web convert <pptx> -o out/` | 转换成静态网页包 |
| `ppt2web inspect <pptx>` | 结构探针：形状/几何/动画行为/字体/媒体清单 + 风险提示 |
| `ppt2web verify <out/> [--pptx 源.pptx]` | 结构化断言（硬门禁）；带 `--pptx` 会回读源文件做端到端比对 |
| `ppt2web export-pdf <out/> -o deck.pdf` | 用本机 Chrome 打印成逐页对齐的 PDF |
| `ppt2web visual-diff <out/> --pptx 源.pptx` | 像素级视觉比对（**探索工具，不做门禁**） |

拿不准一个 PPT 能不能转、难度多大，先跑 `inspect`。

`convert` 还有几个开关：

| 开关 | 作用 |
|---|---|
| `--text vector\|html` | 文字渲染方式（见下面「文字：矢量还是 HTML」） |
| `--wipe-direction motion\|side` | 擦除动画的方向约定（见下面「动画是怎么还原的」） |
| `--mirror-text` | 翻转（`flipH`/`flipV`）的形状，文字也跟着镜像。默认**不**镜像：PowerPoint 翻转形状不会把文字镜像掉 |

## 产物结构

```
out/
  index.html          播放器外壳（等比缩放、控件栏、键盘快捷键）
  runtime.js          播放器逻辑
  slide.js            动画引擎（行为树 → Web Animations API）
  manifest.json       全局信息 + 每页索引 + 媒体哈希 + 字体清单
  print.html          逐页打印视图（PDF 导出用）
  report.html         效果覆盖报告：逐条动画标注 native / approx / dropped
  slides/001.html…    每页一个（天然懒加载、单页可分享）
  assets/
    ppt2web.css       共享样式 + 内嵌字体的 @font-face（仅 HTML 文字模式）
    image1.png…       位图（原样字节）
    fonts/*.woff2     按实际用到的字符子集化的字体（仅 HTML 文字模式）
```

打开方式：`file://` 双击即可（不依赖任何网络），也可以丢到任意静态托管。

`←` `→` 翻页 · `空格` 推进动画 · `Home` `End` 首末页 · `F` 全屏 · `O` 显示/隐藏控件栏

## 文字：矢量还是 HTML

| 模式 | 开关 | 特点 |
|---|---|---|
| **矢量**（默认） | `--text vector` | 文字是字形轮廓。**不依赖字体**、不依赖观看者装没装字体、跨平台渲染一致；换行/行高/字距由我们自己算（和 PowerPoint 对齐）。代价：文字默认不可选中——但 DOM 里保留了一层看不见的真实文本（`.tx-a11y`），搜索、复制、读屏器都还在 |
| **HTML** | `--text html` | 文字是 HTML + 内嵌字体。可选中、体积小，代价是依赖内嵌字体、浏览器排版和 PowerPoint 有细微差异 |

矢量模式遇到**缺字形**（字体没装好）时，那个形状会自动退回 HTML 文字 —— 宁可字形不完美，也不能让文字凭空消失。

## 图表与表格

图表和表格都是**转换期算好、产物里是静态 SVG**（不引任何 JS 库），
坐标和其它图元共用同一套坐标系，所以能和原稿严丝合缝地对上。

| 对象 | 怎么画的 |
|---|---|
| **甜甜圈 / 饼图** | 圆环扇形路径；起始角、洞径（`holeSize`）、每个数据点的显式填充都照抄 OOXML |
| **簇状柱状图** | 绘图区按 `c:manualLayout` 手工定位；网格线、坐标轴标签（**可带旋转**）、柱顶数据标签都画 |
| **表格** | 单元格填充 + 边框（**边框在 `ppt/tableStyles.xml` 里，不在单元格里**）+ 逐 run 保留字号 |

几个必须照着 OOXML 做的细节：

- **类别名/系列名可能不在 `c:cat`/`c:tx` 里**。WPS 生成的图表把它们放进了
  `c15:filteredCategoryTitle` / `c15:filteredSeriesTitle` 扩展 —— 不读就只能
  画出没有标签的柱子。
- **`ptCount` 会撒谎**。有的图表声明 4 个点却只给 2 个 `c:pt`（数据被筛掉了），
  按声明画会多出两个空扇区 —— 一律按**实际存在的点**画。
- **图表可以自带主题**（`c:themeOverride`），配色按覆盖主题算，不是幻灯片主题。
- **坐标轴标签的旋转角**：规范单位是 1/60000 度，但有些生成器（WPS）写的是
  1/1000000 度（`rot="-60000000"` 按规范是 -1000°，荒谬）。超出 ±180° 就按
  1e-6 度解释。
- **表格的边框来自表格样式**，而样式同时还管**文字**（首行白字粗体）——
  单元格里写的填充色覆盖样式的填充，但覆盖不了文字色和粗体。

文字标签同样是**矢量轮廓**（不依赖观看者装字体），并带原生 `<title>` 悬停提示
（零 JS）。

无障碍层：图表是一段文本（系列名 + 类别名），表格是一张**真的 `<table>`**
（`th`/`td` + 行列关联），读屏器能按行列导航。

**HTML 模式**（`--text html`）下图表和表格只画几何、不画标签 —— 文字仍在
无障碍层里，可搜索。矢量模式才是完整的。

## 文字怎么排

浏览器排版和 PowerPoint 一定有偏差，所以矢量模式下**排版是自己算的**
（`ppt2web/render/textlayout.py`），规则照抄 PowerPoint：

- **基线**：行盒比字体内容区高出来的部分，一半放基线之上、一半放之下（CSS 的半行距模型）。
  基线落在 `ascent + 半行距`，不是"行高 × ascent 比例"——后者会把行距重复算一遍，
  整段文字会下沉约半个行距，压到下一段上
- **对齐**：段落级的 `algn`（`l`/`ctr`/`r`/`just`/`dist`）在文字区里生效，不是永远左对齐
- **换行**：`bodyPr wrap="none"` 的文本框不自动换行，整段排成一行横向溢出
- **缩进**：`marL` 是整段的左边界，`indent`（悬挂缩进）只作用于该段的首行
- **禁则**：中文标点不能出现在行首/行尾，标点会挤回上一行
- **渐变文字**：`a:rPr/a:gradFill` 是**文字本身**的渐变（封面标题那种描边渐变）——
  矢量模式要把它翻成 SVG 的 `<linearGradient>`，否则那四个字会变成黑色

## 字体

字体按"**真身优先、替代兜底**"解析：

1. `ppt2web/fonts/local/` 里放了同名字体 → 用**真身**（字形与原稿一致）
2. 否则用度量兼容的开源替代：思源宋体 CN → Noto Serif CN，思源黑体 CN → Noto Sans SC，Calibri → Carlito，Arial → Arimo
3. 字体名里带的字重后缀会被解析（`思源宋体 CN Heavy` → wght 900）

项目内置的字体（`ppt2web/fonts/`）是从 npm 的 fontsource 包导入的：

```bash
# 一次性准备（联网）
npm install --prefix /tmp/ppt2web-fonts \
    @fontsource-variable/noto-serif-sc @fontsource-variable/noto-sans-sc \
    @fontsource/carlito @fontsource/arimo @fontsource/monoton
python tools/import_fonts.py --prefix /tmp/ppt2web-fonts   # 导入到 ppt2web/fonts/
```

导入之后转换器不再需要 npm：字体文件 + `manifest.json`（unicode-range / 字重）+ `fonts.lock.json`（来源与版本）都在项目里。

商用字体（阿里巴巴普惠体、演示夏行楷……）不放进版本库，把字体文件丢进
`ppt2web/fonts/local/` 即可，转换器会自动识别并优先使用。

**文件名不用严格等于 PPT 里的字体名**（商用字体几乎都带版本号）：

| PPT 里的 typeface | 可以用的文件名 |
|---|---|
| `阿里巴巴普惠体` | `阿里巴巴普惠体.ttf`、`阿里巴巴普惠体-3.0 55 Regular.ttf` |
| `思源宋体 CN Heavy` | `思源宋体 CN Heavy.ttf`、`思源宋体CNHeavy.otf` |

匹配顺序：规范化（去空格/连字符/下划线、转小写）后**完全相等** → 去掉字重后缀
再比 → **文件名以字体名开头**（多个候选时挑字重最接近的）。

真身**缺字形**时（常见：中文字体没有西文）会**逐字符**回落到替代字体 ——
而不是让整个形状退回 HTML 文字（那样版式会变，十几页正文会集体塌）。

字体分片是**懒加载**的：一个中文字体有上百个分片，全加载要十几秒，
而一份稿子通常只用到一两个。

## 动画是怎么还原的

PowerPoint 已经把动画写成了精确的行为描述（`p:anim` / `p:animRot` / `p:set` / `p:animEffect` 的
`attrName` + `tavLst` 关键帧），所以**不需要**实现"预设库再近似"——
直接把这棵树翻译成 WAAPI 关键帧，任何预设都自动覆盖，且保真度更高。

入场效果（`p:animEffect`）带的是 `filter="wipe(left)"` 这种精确描述，直接翻成
`clip-path` / `opacity` 就能逐帧一致（`fade`、`wipe(四个方向)`、`circle(in)`、
`barn(inVertical)` 都是原生；`dissolve`、`randombar(...)` 是近似）。

擦除方向有两种读法（OOXML 没说死），用 `--wipe-direction motion|side` 切换：
`motion` = 名字指擦除边缘的移动方向（默认），`side` = 名字指显现的起始边。

触发模型两种都支持：
- **点击组**（`nodeType="clickEffect"`）—— 像 PowerPoint 一样点一下推进一组
- **自动链**（`nodeType="withEffect"`）—— 进页按 delay 自动播

几个容易踩的 OOXML 坑（都踩过）：

- **"等点击"和"随页自动"是两个并列的 cond**：
  `<p:cond delay="indefinite"/><p:cond evt="onBegin" delay="0"/>`
  —— 只看第一个 cond 会把自动播的组全判成点击组
- **`afterEffect` 的"N 毫秒"写在**外层那个 par** 上**
  （效果自己的 cTn 里写的是 0），而且是从**上一个效果结束**开始算的 ——
  当成"点击后 N 毫秒"会让整个时间线提前一截
- **相对位移**（`#ppt_y+.1`）是"当前值 ± 一个量"，值是**整页比例**，
  换算成 EMU 才能用；只认精确名字的话它会静默变成 0（"浮入"效果一动不动）
- **`#ppt_x` → `#ppt_x` 是源文件故意让它不动**（浮入效果里 x 不变、只有 y 变），
  和"相对位移被抹平"是两回事 —— 报告的判定要分得开

## 页面转场

`p:transition`（2D）和 `p14:` 扩展（3D）都读：

- 2D 转场（fade/wipe/push/cover/split/cut/dissolve/zoom）**原生实现** ——
  播放器用两个 iframe 叠着，新页在后台那个加载完再交叉播放
- 3D 转场（`p14:flythrough`）**近似**成"推近 + 淡入"（3D 镜头运动在 CSS 里还原不了）
- `mc:Fallback` 里的退化转场也记下来（老阅读器用它）
- `advTm` = **转场后多少毫秒自动翻页** —— 实现了

## 音频

`<p:audio>` + 形状上的 `<a:audioFile>`：

- 素材**原样落盘**到 `assets/`，页面上放一个隐藏的 `<audio>`
- 命令型动画（`<p:cmd cmd="playFrom(0.0)">`）触发播放（`cmd` 行为和媒体在
  时间轴里是一一对应的）
- 音量、循环都照抄源文件

浏览器的**自动播放策略**会拦掉没有用户手势的播放 —— 这是浏览器的规矩，
绕不过去；元素还在，用户点一下就能播。

## 验收

```bash
python -m ppt2web verify out/ --pptx 某文件.pptx
```

断言分三层：

### ① 结构级（`--pptx` 回读源文件做端到端比对）

- 媒体字节 SHA-256 一致，**且源里引用到的媒体一个都不能少**
  （以前只校验"产物里已有的"，转换时漏掉的媒体对 `verify` 完全隐形 ——
  第 9/17/21 页那 5 张图就是这么丢的）
- 每页图元数一致
- 动画组数、行为数一致，每个动画目标在产物里都有对应节点（动画不断链）
- **文字逐字符对齐**：回读源 PPT 的文字，和产物渲染出来的文字逐字符比（不丢字、不串行、不错序）
  —— 文字包括**表格单元格**和**图表的系列名/类别名**（第 10 页表格那 125 个字，
  以前整个丢了而 `verify` 查不出来）
- **图表/表格不许留占位框**（分级门禁）：我们声称支持的类型必须真的画出来；
  明确不支持的类型才允许留占位框，并且要记进 `report.html`
- 每个用到的字体，要么内嵌了 @font-face，要么在回落清单里
- 动效滤镜都在运行时实现了（判定表和运行时实现表交叉检查）
- **产物里不能出现非法的 SVG paint**（`fill="linear-gradient(...)"` 这类 CSS 串
  写进 SVG 属性，浏览器会忽略 → 形状变黑）
- 报告里 dropped 的行为必须是 0，页面转场必须都实现了
  （以前转场和音频是**静默丢失**的，report 里连一条提示都没有）

### ② 几何级（`ppt2web/verify_layout.py`）

- **尺寸**：每个图元的宽高（EMU）必须和源里 `a:ext` 一致
- **位置**：把分组里的变换一路复合上去后的**绝对矩阵**要和源里一致
- **断行数**：源里写了 `<a:spAutoFit/>` 的文本框，框高是作者软件按它自己的
  行高模型算出来的；用它推出**行数**，和产物实际的行数比 ——
  行数不一样就是断行点变了（字体替代真正带来的排版漂移）

> 行**高**故意不比：这份稿子里的框高一律是 ~1.212×字号（作者软件的模型），
> 而 PowerPoint / LibreOffice / 我们都用**字体度量**（思源宋体 → Noto Serif SC
> 是 1.437em）。实测 LibreOffice 的行距和产物一致、都和源里存的框高对不上，
> 所以那是模型差异，不是 bug。断行数对 1% 的行高差不敏感，才是可靠指标。

### ③ 像素级（**探索工具，不做门禁**）

```bash
python -m ppt2web visual-diff out/ --pptx 某文件.pptx
```

用 LibreOffice 渲原稿、Chrome 打印产物，逐页做像素 diff，输出 diff 图和差异率。

**它是探针不是判官**：LibreOffice 不是 PowerPoint，它在至少三类差异上是错的
（本机缺字体 · `c15` 扩展 · `wrap="none"` · `a:fillRect` 出血），这些页面的
diff 天然很大。所以每页都会标注"有没有已知差异能解释它"——
**没有已知差异、差异又大的页面，才是真正该查的**。

工具会自动给 soffice 喂一份**临时**的 fontconfig 配置（`FONTCONFIG_FILE`），
把源文件里的商业字体指向系统里同源的替代 —— 只是这次调用生效，不改系统配置。

版式漂移多少、行高像不像，最终还是要**目视**：转换完用浏览器打开，和原稿人工比一遍。

## 已知限制

- **SmartArt**（`a:graphicData` 的 diagram）仍只渲染占位框
- 图表只支持**柱状图 / 甜甜圈 / 饼图**；折线、散点、面积、堆积、双坐标轴、
  图例、标题都会**明确降级成占位框**（并在 `report.html` 里注明原因），
  而不是画个"像但不对"的图
- 表格的**合并单元格**暂不支持（同样降级成占位框）
- **3D 页面转场**（`p14:flythrough`）降级成"推近 + 淡入"的近似实现 ——
  3D 镜头运动在 CSS 里还原不了（离轴投影、非等比缩放都对不上）。
  2D 转场（fade/wipe/push/cover/split/cut/dissolve/zoom）是原生实现的
- **音频**已经实现（素材内嵌 + `cmd="playFrom(...)"` 触发播放），但浏览器的
  **自动播放策略**会拦掉没有用户手势的播放 —— 那是浏览器的规矩，绕不过去
- **非同源字体替代会让字形和行高变**（阿里巴巴普惠体 → Noto Sans SC）：
  断行数已核对一致，但字形不同、行高模型不同（见「验收 → ② 几何级」的说明）。
  补上真身字体（`ppt2web/fonts/local/`）即可完全还原
- `a:tile`（图片平铺填充）暂未实现，按拉伸处理
- Wingdings 等符号字体会退化成普通字符
- 不支持 `.ppt`（2007 前二进制）与 `.odp`（需要 LibreOffice）

## 图片填充（`a:blipFill`）

"形状被一张图填充"（`<p:sp>` + `a:blipFill`）和图片图元（`<p:pic>`）是**两回事**：
第 9/17/21 页的照片就是这么放的（不是 `<p:pic>`），不处理就整张丢光。

- 图片按 `a:fillRect` **拉伸**铺到那个矩形（负的内缩 = 图片比形状大，出血），
  再由形状轮廓裁掉 —— 和 OOXML 的字面语义一致
- 不用 CSS `clip-path`：它吃不了任意 SVG path（预置几何/自定义几何都是 path 数据），
  所以用 SVG 的 `<clipPath>`
- `a:tile`（平铺）暂未实现，按拉伸处理
